# 侧边栏适配与能力校验

侧边栏连接不再用 Android SDK、versionCode 或 versionName 精确放行。仍校验系统／更新系统应用标记、启用状态、UID、服务进程、导出状态和组件权限；消息的调用方 UID 与协议版本校验保持不变。通过身份校验不代表所有功能可用。

## 字节码解析

DexKit 2.3.0 在侧边栏包 ClassLoader 就绪后启动一次后台解析：

- 方向判断从 `MainPanelSizeHelper.getPanelGap()` 的两个布尔调用出发，校验共同依赖和已核对的分支指令形态，区别横屏与小屏竖屏；悬停模式通过日志字符串与签名定位。保留厂商折叠、旋转及平板判断，不用模块自己的屏幕宽高替代。
- v2 阴影更新从主面板真实调用中定位 `(View, float)` 静态方法，允许直接调用 `setElevation`，或经同类的一层静态委托调用；初始化方法必须属于同类，并由主面板或其内部回调实际调用，避免同签名方法歧义。不会递归遍历任意调用图或取第一个候选。
- Kotlin Unit 从返回 `kotlin.Unit` 的 `toString()` 和该类唯一静态自身类型字段定位，不再硬编码混淆后的类名。
- 新式模糊通过 attach/release 日志、方法签名和 invalidate 调用定位实例管理器，区分三参数 attach 与新增背景兜底颜色参数的四参数 attach。四参数形式保存同类的静态 synthetic 默认参数桥，按已核对的宿主调用传入掩码 `8`，由宿主选择默认颜色 `0`，不猜测颜色语义或硬编码混淆方法名；缓存类型为 `platform-default`。旧式模糊通过初始化日志、ViewRootManager 调用和支持条件调用图定位静态工具。调用方式与释放语义分别保留。

每个目标必须唯一命中。方向或 Unit 解析失败时，“全部”面板拒绝打开；阴影单独不可识别时记录诊断并关闭阴影，面板继续使用已校验的内容和几何能力；模糊单独不可识别时记录诊断并使用原有不透明卡片背景。不可识别的新结构不能靠取第一个候选强行启用。

解析结果以 APK SHA-256 和规则版本为缓存身份，保存完整成员描述符与独立的 `shadowKind`、`blurKind` 能力状态。阴影可用时必须同时包含初始化和更新方法，不可用时不得保留其中任一方法；未知能力类型、残缺成员和旧缓存格式均被拒绝。缓存命中仍校验类型、参数、返回值和静态／实例关系，缓存不可用时重新解析一次。读取 APK、缓存和 DexKit 查询均在后台完成，宿主单例与 View 仍在主线程创建。十秒超时后放弃发布结果并请求中断；native 查询不能保证立即中断，返回后释放 bridge，不保留常驻线程池。

## 页面能力

关闭入口按实际内容树选择工具栏取消菜单或旧式关闭 View。两个旧式搜索 Animator getter 分别按是否存在检测，不再根据 SDK 推断。缺少必需资源、业务方法或关闭控件仍按既有失败清理路径退出。

目录和启动仍调用宿主具名业务接口；Provider 的准备方法、Service 名称、目录分类语义、资源名称和 IPC 协议没有变成“任意版本通用”。厂家修改这些行为时仍需研究，DexKit 仅降低混淆改名带来的维护成本。

## 验证

本地 APK 回归使用 `SidebarDexQueryTest`：`FLYMEFREEFORM_TEST_SIDEBAR_FIXTURES` 指向 TSV，每行包含 APK 绝对路径和已人工核对的 `key=descriptor` 文件路径；`FLYMEFREEFORM_TEST_DEXKIT_LIBRARY` 指向同版本的桌面 native 库。未提供时跳过该项，更换样本时需重新执行测试。

本地回归样本包含侧边栏 16.14.0、16.14.6、17.9.2，以及用户提供的 17.9.8 和当前设备提取的 17.9.8，共五个 APK。验证范围是字节码、资源与签名的静态核对及本地查询回归；查询通过不代表所有后续版本兼容。新模块尚未完成真机面板打开、搜索、点击、关闭与旋转等交互验证。
