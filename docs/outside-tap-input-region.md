# 窗外点击与输入法避让

FlymeFreeform 是面向 ColorOS 的非官方独立实现。

窗外单击或双击关闭启用时，模块扩展系统小窗标题层的触摸区域，从按下事件开始接住窗外触摸。状态栏、可见输入法、系统排除区及其他小窗仍使用原有输入通道。关闭判定仍要求普通小窗、单指短点击和已建立的区域保护。

## 输入法下的边界

ColorOS 17 的输入法避让会平移、裁短小窗，并单独调整标题层布局。`FlexibleTaskController.getFlexibleTaskVisibleBounds(Task)` 仍由 `Task.getBounds()` 和缩放比例计算，不能代表所有输入法避让状态。

模块通过 `Task.getWrapper().getExtImpl()` 读取 `TaskExtImpl.getFlexibleTaskPosAfterIme()`；结果非空时使用该屏幕边界，空时才使用普通可见边界。读取后复制 `Rect`，不修改系统保存的对象。保护区域、其他小窗的排除区域和窗外点击判定共用这一规则。

标题层的本地尺寸与选定边界共同确定坐标换算。仍保留尺寸与等比缩放校验；输入法高度变化不能通过放宽校验或沿用旧任务尺寸绕过。Hook 原方法每次只执行一次，反射或状态异常沿用已有失败开放路径。

## 验证边界

ColorOS 17 / Android 17 真机采样确认：输入法服务于小窗时，标题层变矮，两侧屏幕边缘失去扩展触摸区域；输入法服务于底层应用时，标题层保留原高度，扩展区域存在。系统框架确认输入法避让边界与普通任务边界分别保存。

修复后的 APK 尚需真机回归：键盘显示及收起、左右窗外单击与双击、键盘输入、底部手柄、其他小窗、拖动缩放、旋转，以及关闭增强后的恢复行为。编译和单元测试不能代替这一验证。
