# 横屏与游戏模式暂停

设置页提供“横屏时暂停”和“游戏模式时暂停”两个独立开关，默认开启。已有配置没有这两个键时也使用开启默认值。配置写入同一组框架远程偏好，各注入进程读取相同的规则；设置页本身仍可使用。

任意一条已开启的暂停规则命中时，模块暂停边角手势、扇形与更多应用面板、手柄上滑到迷你窗、点外部关闭等增强。正在进行的选择被取消，输入热区和临时窗口被移除，扩展的窗外触摸区域请求恢复为系统区域。已打开的小窗继续由 ColorOS 管理。所有已开启的暂停条件解除后，按原有功能配置恢复，不改变模块总开关。

关闭某一暂停开关，只解除对应场景限制。例如横屏游戏同时命中两条规则，只关闭“横屏时暂停”仍会因游戏模式而暂停。关闭限制不代表该场景的所有交互已经完成兼容验证。边角手势仍要求手势导航且未锁屏。

横竖屏根据默认显示的当前宽高判断，使用显示监听更新，避免桌面或小窗自己的固定竖屏配置遮蔽实际横屏。游戏模式使用当前 ColorOS 的 `Settings.Global/debug_gamemode_value` 信号，并通过设置观察者更新，不扫描游戏应用列表，也不修改系统游戏设置。

环境读取与通知由进程内的 `ModuleEnvironmentState` 持有；系统进程内的窗口增强共享同一个实例。触摸路径读取缓存，启动、显示与设置变化时才刷新环境。侧边栏服务销毁时释放监听，其余实例跟随所属进程生命周期。

锁屏通知接收器仅监听受系统保护的屏幕开关、用户解锁及解锁完成广播。解锁完成通知由独立 UID 的 SystemUI 发送，因此允许跨进程投递；收到后重新读取 `KeyguardManager`，不从广播参数推断已解锁。配置刷新时也重新核对仍处于锁定状态的缓存，避免恢复监听依赖过期结果。

桌面已经拦下按下事件的指针流在暂停后只做收尾，不再抢占或触发动作；不会将缺少按下事件的后半段输入交回原处理器。后续新指针流正常交还系统。延迟启动和面板执行前再次检查环境，防止暂停后执行排队中的选择。
