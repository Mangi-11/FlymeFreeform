# 扇形快捷项

扇形最多固定六项，应用、分身应用、侧边栏工具与快捷入口共享同一份顺序。选择和排序保存在 Flyme 小窗的模块配置中，不修改智能侧边栏的已选列表。

## 目录范围

- 应用：当前用户可启动的桌面应用。
- 工具：当前 ColorOS 智能侧边栏提供且未隐藏的工具。
- 快捷入口：侧边栏已提供的快捷方式，以及其特殊应用入口。
- 分身应用：侧边栏当前可用且未隐藏的分身桌面入口，与同包名的本体分别固定。

目录连接不再按侧边栏版本号与 SDK 精确放行，仍校验系统包及受保护组件身份；目录分类和启动路由继续要求宿主具名接口满足现有协议。视觉接口的解析与验证边界见 [侧边栏适配](sidebar-dex-resolution.md)。需要开启智能侧边栏，且 `system`、SystemUI、桌面和智能侧边栏这四个现有作用域均生效。不额外向目标应用注入。

目录只接入当前前台用户及其由侧边栏确认的分身入口，不接入任意其他用户的应用。侧边栏不可用时仍可管理普通应用，但不能新增分身项。侧边栏能提供哪些快捷入口取决于其桌面数据、隐藏规则和系统功能状态，不能理解为所有应用发布的全部 Android 快捷方式。

进入快捷项页面时读取目录；读取失败会显示重试入口，仍可管理普通应用和移除已有固定项。缓存仅用于显示名称、图标，失败时不能从旧目录添加新的工具或分身应用。失效的固定项不会自动替换成其他应用，已保存的身份仍保留，便于恢复或手动移除。

## 配置与执行

`corner_targets_v2` 是固定项唯一读写事实源。没有该键时读取旧 `corner_pins_v1`，将组件规范化并保持顺序；下一次成功保存配置时写入新键并移除旧键。明确保存的空列表始终表示只保留“更多”，不会回退到最近应用。

新身份分别表示应用组件、工具 alias、快捷方式 alias、特殊应用入口 alias 与分身应用 alias；侧边栏身份额外包含所属用户。分身与本体即使包名和 Activity 相同也不会合并。不持久化或跨进程接收任意 Intent。

普通应用继续使用系统自由窗启动链路。侧边栏项在菜单移除后启动短连接，等待侧边栏准备就绪，系统端再核对前台窗口、旋转、配置和手势运行环境。后续触摸、取消或超时会放弃待执行动作。侧边栏执行前在工作线程重新从有效目录定位目标，主线程只调用一次相应原生路由；分身应用由该路由携带所属分身用户启动。原生路由决定工具或快捷入口的实际呈现方式，不强制所有工具进入小窗。

## 通信边界

设置页请求只提供目录读取能力。动态广播接收器要求模块的签名权限，并再次核对系统提供的发送包名、UID 和当前用户。绑定侧边栏仍经过原有厂商服务权限；新增 Binder 协议只接受 system UID，不向 App 暴露执行请求入口。

每次连接有七秒期限，目录最多 256 项，图标最多 96 × 96 像素，逐项通过框架类型传输。只有条数与顺序完整、无重复身份的结果才发布。请求完成、取消、超时或 Binder 死亡后释放连接；有效期内的重复请求不会再次执行。

## 验证边界

本次接入覆盖了配置迁移、混合身份、顺序与上限、目录传输完整性以及请求重放的单元测试。构建检查与真机可用性分别判断。

分身目录与启动路由尚未进行安装后的真机回归，尤其需要核对同包名本体与分身的区分、分身停用或删除、侧边栏关闭、旋转和锁屏。工具实际启动、识屏与截屏不包含菜单、冷启动、侧边栏退出、多用户、应用卸载和连续手势也仍需回归。编译通过不代表这些交互已在设备上验证。
